# AeroSentinel — uncertainty-aware jet engine prognostics

Predicts remaining useful life (RUL) of turbofan engines on NASA N-CMAPSS (real flight profiles), with conformal prediction intervals, sensor attributions, a cost-aware maintenance policy, an ONNX/FastAPI service and a Streamlit dashboard. Full spec: @docs/SPEC.md. Current phase and task list: @docs/PHASES.md.

## Commands
- Env: `uv sync` (Python 3.11). Never `pip install` directly; add deps with `uv add <pkg>`. torch comes from the PyTorch CPU index (pinned in pyproject); never pull CUDA wheels locally or in CI.
- Data: `uv run python scripts/download_data.py {cmapss,ncmapss}` (also `make data-cmapss` / `make data-ncmapss`)
- Lint/format: `uv run ruff check . --fix && uv run ruff format .`
- Types: `uv run mypy src`
- Fast tests: `uv run pytest -q -m "not slow"`; full: `uv run pytest -q`
- Train: `uv run python -m aerosentinel.train experiment=<name>` (Hydra configs in `configs/`)
- Dashboard: `uv run streamlit run app/dashboard.py`
- API: `uv run uvicorn aerosentinel.serve.api:app --reload`

## Hard rules (IMPORTANT)
- Splits are ALWAYS by engine unit, never by window or row. A unit's windows live in exactly one of train / val / calib / test.
- Tuning on dev units (policy thresholds, margins, unit-level conformal calibration) uses out-of-fold predictions only.
- Model inputs are only W (4 flight descriptors) + X_s (14 measured sensors), plus the per-engine healthy-baseline residuals derived from them.
  - NEVER feed X_v, theta (health params), hs (health state) or RUL-derived columns as features: they leak the label.
  - NEVER feed unit or cycle either. Unit gives the model engine identity, and cycle lets it learn a life-length prior instead of reading health from the sensors.
- N-CMAPSS windows never cross a (unit, cycle) boundary or splice non-contiguous cruise samples. Test stride = train stride. Primary metrics are per cycle (median of the cycle's window predictions).
- Intervals target 90% marginal per-cycle coverage (alpha = 0.10). The alpha_lo/alpha_hi split follows the SPEC §6 rule (≥ 60 calibration units → 0.02/0.08, else 0.05/0.05).
- `data/raw/` is written only by `scripts/download_data.py`. Never edit, move or delete files there by hand. Checksums live in the tracked `configs/data_checksums.txt`. Derived data goes to `data/processed/` (gitignored). Never materialize window caches: use per-unit arrays + a window index.
- Never commit data or model weights > 5 MB. The one exception is the demo bundle in `app/demo_data/`, which must stay ≤ 10 MB, or else it is hosted as an HF dataset.
- Every reported number comes from a script in `scripts/` that writes `reports/results/<dataset>_<model>_<setting>.json` (naming in SPEC §4; experiment name = file stem). README tables are generated by `scripts/make_tables.py`, never typed by hand.
- Write expected findings as hypotheses, and report what actually happened, including negative results.
- Fix seeds (`aerosentinel.utils.seed_everything`). Report mean ± std over ≥3 seeds.
- Don't claim "state of the art". Protocols differ across papers; compare only against baselines we re-ran under our protocol.

## Style
- `src/` layout, type hints everywhere, small pure functions, numpy-style docstrings on public functions.
- Large arrays: memory-map or chunk HDF5 reads with h5py; don't load all subsets at once.
- When compacting, preserve: current phase, list of modified files, last test command and its result.

## Done means
A task is done only when ruff, mypy and fast tests pass and you've shown the command output. For model changes, also show the metrics JSON diff.
